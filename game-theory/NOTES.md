## User preferences (from the initiating brief)

- **Feynman technique, strictly.** Intuition and "why" before formal terms; minimal jargon; math only when it earns its keep, and always plain-English-first when it appears.
- **Interactive cycle required, not optional.** Explain → Example → Test → Scenario → Your Answer → Feedback → Deeper Concept → New Scenario. Every lesson should ask questions and let the user reason before revealing answers, not just narrate.
- **Wrong answers get a hint + retry, not the answer.** When the user answers incorrectly, identify where the reasoning broke, give a hint, let them try again, then explain.
- **"Game Theory Detective" exercises wanted periodically** — give a real-world-shaped scenario and make the user identify which game/concept is at play, unprompted.
- **Quiz formatting rule (repo-wide convention, reused here):** for any multiple-choice quiz, keep all answer options the same approximate length/word count so formatting doesn't leak the answer.
- **Self-contained guide** (repo convention): lessons must teach the full concept themselves; external sources are for trust/depth, not prerequisites.
- **Bring-your-own-situations is core, not a bonus.** The user explicitly wants to submit real situations at any time for Players → Incentives → Information → Strategies → Payoffs → Timing → Repeated Interaction → Equilibrium → Alternatives → Best Response analysis — this can happen mid-curriculum, not just as a capstone.
- Likely context (inferred, not confirmed): salary example used ₹25 LPA — user is probably an India-based professional, plausibly in tech given the sibling `javascript/` workspace in this repo. Use realistic tech-industry and India-relevant examples (salary negotiation in LPA, product companies, IT services) where it doesn't distort the concept.

## Roadmap (from the initiating brief — 10 levels, see index.html for live status)

1. Foundations (players, actions, strategies, payoffs, info, rationality, common knowledge, zero-sum vs non-zero-sum, cooperative vs non-cooperative)
2. Simple strategic problems
3. Payoff matrices, dominant/dominated strategies, best response, Nash equilibrium, Pareto efficiency, mixed strategies — taught through the classic games (Prisoner's Dilemma, Battle of the Sexes, Chicken, Stag Hunt, Matching Pennies, Ultimatum, Dictator, Trust, Public Goods, Coordination, Free-Rider, Tragedy of the Commons)
4. Sequential games (game trees, backward induction, credible/non-credible threats, commitment, first/second-mover advantage, deterrence, entry games)
5. Repeated games (reputation, Tit-for-Tat, Grim Trigger, forgiveness, long-term incentives)
6. Incomplete/asymmetric information (moral hazard, adverse selection, Bayesian reasoning, Market for Lemons)
7. Signaling and reputation (cheap talk vs costly vs credible vs manipulative signals)
8. Negotiation (BATNA, ZOPA, anchoring, commitment, bluffing, deadlines) — applied to salary, freelance pricing, buying a car, business deals
9. Business & competitive strategy (pricing, entry/exit, network effects, switching costs) + Auctions (first-price, second-price/Vickrey, winner's curse)
10. Mechanism design, evolutionary game theory, behavioral game theory (bounded rationality, biases) — advanced/capstone tier

Plus, threaded throughout rather than a separate module: "Game Theory in Everyday Life" (career, business, relationships, social, personal, investing) and the reusable 20-question Game Theory Lens / one-page decision framework (build as a reference doc once enough vocabulary exists to populate it meaningfully — premature right now).
