Interview framework (45 min)

  1. Clarify requirements — functional (features) + non-functional (scale, latency, consistency)
  2. Estimate scale — DAU, QPS, storage (back-of-envelope)
  3. High-level diagram — client → CDN → LB → API → services → DB/cache/queue
  4. Deep dive — data model, API design, bottlenecks, failure modes
  5. Trade-offs — why this over that; mention alternatives

Questions to ask

  • Read-heavy or write-heavy?
  • Strong consistency or eventual consistency OK?
  • Real-time requirements (WebSockets)?
  • Multi-region? Mobile + web?
  • Auth model — sessions, JWT, OAuth?

Classic designs — talking points

URL shortener

  • Generate unique short code (base62) — DB unique index or counter + encode
  • Read-heavy → Redis cache mapping short → long URL
  • 302 redirect on GET /:code
  • Analytics — async queue for click events

Social feed (Twitter-like)

  • Fan-out on write — push to followers' feeds (good for celebrities problem: hybrid)
  • Fan-out on read — merge at read time (simpler, slower for hot users)
  • Redis sorted sets for timeline; Postgres for posts/follows
  • React infinite scroll + React Query pagination

Chat / realtime

  • WebSockets (ws/Socket.io) or SSE for server push
  • Redis pub/sub or dedicated message broker between API instances
  • Store messages in Postgres; deliver via WS; presence in Redis
  • Node handles many concurrent WS on event loop — scale horizontally with sticky sessions or shared pub/sub

E-commerce checkout

  • Inventory reservation — DB transaction or optimistic locking
  • Payment — idempotency key, saga with compensate on failure
  • Order service + payment service + notification queue
  • Redis for cart session; Postgres for orders

Rate-limited public API

  • API Gateway or middleware — token bucket in Redis
  • 429 + Retry-After header
  • Per-user and per-IP limits

Back-of-envelope

1M DAU × 10 requests/day = 10M requests/day
≈ 115 QPS average (×10 peak ≈ 1,150 QPS)

1KB per record × 100M records = 100 GB storage

Diagram checklist

  • Draw boxes: Client → LB → API → DB, Cache, Queue
  • Label read vs write paths
  • Show where auth happens
  • Mention failure: DB down, cache miss, retry, circuit breaker
  • Observability: logs, metrics, traces with correlation ID
