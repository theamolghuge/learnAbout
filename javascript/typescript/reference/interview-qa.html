Basics

What is TypeScript and why use it?

A typed superset of JavaScript that compiles to JS. Catches errors at compile time, improves IDE autocomplete/refactoring, documents APIs via types, and scales better in large codebases. Types are erased at runtime — no performance cost.

Difference between TypeScript and JavaScript?

TypeScript adds static type checking, interfaces, generics, enums, and compile-time analysis. JavaScript runs directly; TypeScript must be compiled (tsc, esbuild, swc) or transpiled on the fly (ts-node). All valid JS is valid TS (with strict settings, implicit any may error).

Types

any vs unknown vs never?

any disables type checking — escape hatch, avoid. unknown is type-safe top type — must narrow before use. never represents values that never occur — functions that always throw, exhaustive switch default.

interface vs type?

Both define object shapes. Interfaces support declaration merging and extends. Types support unions, intersections, mapped/conditional types. Use interface for public object contracts; type for unions and complex transformations.

What is type inference?

TypeScript deduces types without explicit annotations — variable initialization, return types, generic parameters. Best practice: annotate public APIs and function parameters; let inference handle locals when obvious.

Generics

What are generics and why use them?

Type parameters that make functions/classes work with multiple types while preserving type relationships. function identity<T>(x: T): T — input and output stay same type. Avoid duplication and unsafe casts.

What is extends in generics?

A constraint — <T extends string> means T must be assignable to string. <K extends keyof T> ensures K is a valid key of T. Enables safe property access on generic objects.

Narrowing

What is a discriminated union?

Union of object types sharing a literal discriminant field (e.g. kind or type). Switch/if on discriminant narrows to specific member — TypeScript knows which fields exist. Pattern for API results, Redux actions, state machines.

What is a type guard?

Function returning x is Type predicate — tells compiler to narrow type in true branch. Built-in: typeof, instanceof, in. Custom guards for runtime validation (often paired with Zod).

Utility Types

Explain Partial, Pick, and Omit.

Partial<T> — all properties optional (update DTOs). Pick<T, K> — select subset of keys. Omit<T, K> — exclude keys. All derive from existing types — single source of truth.

What is ReturnType<typeof fn>?

Extracts the return type of a function type. Useful when wrapping functions or building on existing APIs without duplicating type definitions.

Advanced

What does satisfies do?

Validates a value matches a type while preserving the narrower inferred type (literal types, specific keys). Unlike as Type which widens/loses inference. TS 4.9+ — great for config objects and route maps.

What is as const?

Assertion making value deeply readonly with literal types — "hello" not string. Used for tuple types, enum-like objects, and discriminant maps.

React & Node

How do you type React component props?

Interface or type for props object; destructure in parameters. Use React.ReactNode for children, React.ChangeEvent<HTMLInputElement> for events. Generic components: <T> on function. ComponentProps<typeof Button> to extract props from existing component.

How does Zod integrate with TypeScript?

Define schema once, infer type with z.infer<typeof Schema>. Runtime validation at API boundary + compile-time types from same source — no drift between validation and types.
