JSX

JSX is syntactic sugar for React.createElement(type, props, ...children). It is not HTML — attribute names and behavior differ.

  • Expressions only — use { } for JS; statements (if/for) belong outside or in IIFEs.
  • One root — use fragments <>...</> to avoid extra DOM nodes.
  • className, htmlFor, tabIndex — camelCase DOM properties.
  • Style objects — style={{ marginTop: 8 }} (px auto-appended for numbers).
  • Boolean attributes — disabled omits attribute when false; string "false" is truthy in HTML.
  • Children — text, elements, arrays, render functions (via props, not JSX children syntax).
{condition && <Alert />}
{items.map(item => <Row key={item.id} {...item} />)}

Components

Function components are the standard. They are plain functions that return React elements and may call hooks.

  • Composition over inheritance — pass UI via children or slot props (header={
    }).
  • Presentational vs container — separate data/logic from markup; hooks often replace container classes.
  • Pure components — same props → same output; no side effects during render.
  • Legacy patterns — HOCs (withAuth(Component)), render props — know for maintenance/interviews, prefer hooks.
  • Refs to DOM — forwardRef for reusable inputs; React 19 allows ref as regular prop on function components.

State & Immutability

React re-renders when state or props change. Updates must be immutable — mutate nothing React owns.

  • useState — lazy init: useState(() => expensive()); functional updates: setCount(c => c + 1).
  • useReducer — complex transitions, explicit actions, easier to test; pairs well with Context for localized "stores".
  • Batching — React 18 batches all updates (including promises, timeouts, native handlers) in one render.
  • Stale closures — effects and callbacks capture values from render; fix with deps, refs, or functional updates.
  • Immutable patterns — spread for objects; map/filter for arrays; Immer for deep trees.
  • State colocation — lift state only as high as needed; avoid global state for local UI.

Events, Lists & Keys

Synthetic events

React wraps native events for cross-browser consistency. Events delegate at the root (React 17+: container from render tree). Call e.persist() only in legacy code — pooling removed in React 17+.

Lists & keys

  • Keys must be stable, unique among siblings — prefer IDs, not array index (except static lists).
  • Wrong keys cause state bugs (input values "jumping") and poor performance.
  • Do not generate keys with Math.random() on every render.

Controlled vs uncontrolled

  • Controlled — React state is source of truth: value={x} onChange={...}.
  • Uncontrolled — DOM holds value; read via ref. File inputs are typically uncontrolled.

Hooks

Hooks let function components use state, lifecycle, and context. Rules: only call at top level; only from React functions or custom hooks.

useState / useReducer

Local component state. Reducer for multi-field updates and explicit action types.

useRef

Mutable box persisting across renders. DOM refs, timers, previous values, avoiding stale closure in callbacks.

useContext

Subscribe to nearest Provider. All consumers re-render when value changes — split contexts or memoize value object to optimize.

useEffect ⭐

Synchronizes component with external systems (DOM APIs, subscriptions, logging, non-React widgets). Not for transforming data for render (derive during render) or user events (use handlers).

  • Dependency array — omit = every render; [] = mount/unmount only; include all reactive values used inside.
  • Cleanup — return function runs before next effect and on unmount; prevents leaks and race conditions.
  • Race pattern — abort flag or AbortController when fetch identity changes.
  • Strict Mode (dev) — double mount simulates remount; effects must be idempotent.
  • eslint-plugin-react-hooks — treat exhaustive-deps warnings seriously; document intentional omissions.
useEffect(() => {
  const ctrl = new AbortController();
  fetch(url, { signal: ctrl.signal })
    .then(r => r.json())
    .then(setData)
    .catch(e => { if (e.name !== 'AbortError') setError(e); });
  return () => ctrl.abort();
}, [url]);

useLayoutEffect

Runs synchronously after DOM mutations, before paint. Use for measuring layout, focus, scroll sync — avoid for data fetching (blocks paint).

useMemo / useCallback

Cache expensive computations and stable function references. Use when profiling shows benefit or when referential equality matters (memoized children, effect deps). Overuse adds memory and comparison cost.

useId

Stable IDs for accessibility (htmlFor / aria-labelledby). Unique per component instance; safe for SSR.

useSyncExternalStore

Subscribe to external stores (Redux, Zustand internals). Ensures tearing-safe reads during concurrent rendering.

useTransition / useDeferredValue

Mark updates non-urgent (startTransition) or defer a value — keep UI responsive during heavy renders. Part of Concurrent React.

useImperativeHandle

Customize ref handle exposed to parent when using forwardRef.

Custom Hooks

Extract stateful logic into reusable functions named useSomething. They compose built-in hooks.

  • Examples — useDebounce, useLocalStorage, useMediaQuery, useFetch (prefer React Query in production).
  • Testing — test with renderHook from Testing Library.
  • Contracts — return stable API; document whether callbacks must be memoized.
function useDebounce<T>(value: T, ms: number) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), ms);
    return () => clearTimeout(id);
  }, [value, ms]);
  return debounced;
}

Communication & Forms

  • Parent → child — props.
  • Child → parent — callback props.
  • Sibling — lift state to common ancestor or shared store.
  • Context — theme, locale, auth snapshot — avoid high-frequency updates.
  • Controlled forms — single state object or per-field; validate on blur/submit.
  • Lifting validation — schema-driven (Zod/Yup) beats ad-hoc checks at scale.

React Hook Form + Zod

Industry standard for performant forms: uncontrolled inputs by default (via refs), minimal re-renders, schema validation with Zod.

  • Why RHF — avoids re-render per keystroke; good DX with TypeScript inference from Zod schema.
  • zodResolver — bridges Zod to RHF's validation pipeline.
  • register vs Controller — native inputs use register; MUI/controlled third-party widgets use Controller.
  • Server errors — setError('root', { message }) or field-level from API.
  • Default values — from props/async load via reset() when data arrives.
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  age: z.coerce.number().min(18),
});

type FormData = z.infer<typeof schema>;

function SignupForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
  });
  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('email')} />
      {errors.email && <span>{errors.email.message}</span>}
    </form>
  );
}

API, React Query & Redux

Server state vs client state

  • Server state — async, shared, cacheable, can stale — React Query / SWR / RTK Query.
  • Client state — UI toggles, wizard step, selections — useState, Context, Zustand, Redux.

React Query (TanStack Query)

  • useQuery — fetch, cache, background refetch, stale-while-revalidate.
  • useMutation — POST/PUT with optimistic updates and rollback.
  • queryKey — hierarchical cache identity; invalidate on mutations.
  • Prefetching — queryClient.prefetchQuery on hover/route load.

Redux Toolkit

  • Single store, time-travel debugging, middleware — still valid for complex client workflows.
  • RTK Query — overlaps React Query; pick one per app for server cache.
  • Selectors — memoized derived data with createSelector.

Anti-patterns

  • Duplicating server data in Redux and React Query.
  • Fetching in useEffect without cancellation, deduplication, or cache.

Rendering & Reconciliation

  • Render phase — pure; builds new element tree; can be interrupted (Concurrent).
  • Commit phase — applies DOM changes; runs layout effects and passive effects.
  • Reconciliation — diff old vs new tree; same type → update props; different type → unmount/remount.
  • Keys — identify list items across moves; without keys React matches by index.
  • Bail out — memo, PureComponent, class shouldComponentUpdate.

Performance

  • Profile first — React DevTools Profiler, why-did-you-render (dev).
  • Split contexts — separate fast-changing from stable values.
  • Virtualize lists — react-window / TanStack Virtual for long lists.
  • Defer non-critical UI — lazy, Suspense, route-based code splitting.
  • Avoid inline object/function props to memoized children unless negligible.
  • Web Workers — heavy computation off main thread.
  • React Compiler — future: auto-memo; today manual optimization where measured.

Concurrent React

React 18+ can interrupt rendering, prioritize updates, and resume later.

  • createRoot — enables concurrent features (vs legacy ReactDOM.render).
  • Suspense — declarative loading boundaries; data frameworks integrate via throwing promises.
  • useTransition — mark state updates as transitions (low priority).
  • useDeferredValue — lag behind fast-updating input for expensive derived UI.
  • Selective hydration — prioritize interactive regions (framework-level, e.g. Next.js).

Hydration

Client attaches event listeners and reconciles against server HTML. Mismatch (Date.now, random IDs, browser-only APIs during SSR) causes warnings and full client re-render.

Server Components

  • Run only on server; can async/await DB directly; no hooks or browser APIs.
  • Pass serializable props to Client Components ('use client').
  • Reduce JS sent to browser; keep interactivity in client islands.

Router & Auth

React Router v6+

  • Nested routes, layout routes, relative links.
  • Data APIs: loader, action, useLoaderData, error boundaries per route.
  • Navigate for redirects; Outlet for child rendering.

Auth patterns

  • Protected routes — wrapper checking auth context; redirect to login with return URL.
  • Token in memory — safest from XSS theft vs localStorage; refresh via httpOnly cookie.
  • SSR auth — read session cookie on server; pass user into RSC/layout.
  • OIDC/OAuth — PKCE for SPAs; BFF pattern for token handling.

Security, Testing & A11y

Security

  • React escapes JSX text — XSS mainly via dangerouslySetInnerHTML or injecting URLs (javascript:).
  • Sanitize HTML (DOMPurify) if rich text required.
  • CSRF — SameSite cookies, CSRF tokens for cookie-based auth.
  • Dependencies — supply chain audits; avoid exposing secrets in client bundles (NEXT_PUBLIC_* is public).

Testing

  • RTL — query by role/label; fire events; assert outcomes, not implementation.
  • MSW — mock network at HTTP layer for integration tests.
  • Avoid — testing internal state, shallow render-only snapshots without behavior.

Accessibility

  • Prefer native elements (button, input) over div click handlers.
  • Focus trap and restore focus in modals; aria-modal, labelled dialogs.
  • Live regions for dynamic announcements (role="status").
  • Keyboard: all interactive paths reachable; visible focus styles.

Fiber & Internals

Fiber is React's unit of work — a linked tree of nodes with alternate (current vs work-in-progress) pairs.

  • Scheduler — prioritizes updates (user input > transition > idle).
  • Lanes — bitmask priority model for batching related updates.
  • Double buffering — build new tree, swap on commit.
  • Effect list — fibers with side effects linked for flush after commit.
  • Why it matters — explains Strict Mode remount, interruptible render, Suspense architecture.

Production & Web Vitals

Core Web Vitals

  • LCP — largest contentful paint < 2.5s — optimize images, fonts, SSR critical path.
  • INP — interaction to next paint — reduce main-thread blocking, split long tasks.
  • CLS — layout shift — reserve space for images/ads, avoid injecting above content.

Production checklist

  • Production build, tree shaking, minification.
  • Error boundaries + global error handler (Sentry).
  • Source maps uploaded privately, not served publicly.
  • CDN cache headers for static assets (content hash filenames).
  • Environment-specific config; no secrets in client.
  • Health checks, graceful degradation when API fails.

React Native (Brief)

React paradigm for iOS/Android using native views instead of DOM. Share logic (hooks, business rules); platform-specific UI via Platform.OS or separate files (.ios.tsx / .android.tsx).

Core components

  • View, Text, ScrollView, FlatList, Pressable, Image — map to native widgets.
  • FlatList — virtualized lists; prefer over mapping huge arrays in ScrollView.
  • StyleSheet — flexbox layout (defaults differ: flexDirection: 'column').

Navigation

  • React Navigation — stack, tab, drawer navigators; deep linking; screen params.
  • Native stack uses platform transitions; JS stack more customizable.

Bridge / New Architecture

  • Legacy bridge — async JSON batch between JS thread and native modules — serialization bottleneck.
  • JSI (New Architecture) — direct C++ interface; synchronous native calls possible; Fabric renderer, TurboModules.
  • Know trade-offs: RN for shared team velocity vs fully native for peak performance / platform APIs.

React 19

  • use hook — read promise or Context in render; integrates with Suspense; can be called conditionally (unlike other hooks in some cases — follow docs).
  • Actions — async functions passed to forms (action / formAction); automatic pending state.
  • useActionState — [state, dispatch, isPending] = useActionState(action, initialState) — replaces useFormState naming.
  • useOptimistic — optimistic UI while async action completes.
  • Ref as prop — no forwardRef required on function components.
  • Document metadata — native support for <title>, <meta> in components.
  • Improved Suspense — pre-warming, better streaming SSR behavior.
  • React Compiler (stable trajectory) — compile-time memoization reducing manual hooks.
// React 19 — use() with Suspense
function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return comments.map(c => <p key={c.id}>{c.text}</p>);
}
