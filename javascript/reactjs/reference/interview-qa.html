React.js Interview Q&A

Comprehensive questions with concise senior-level answers.

Fundamentals

Q1. What is JSX and how does it differ from HTML?

JSX is syntax sugar for React.createElement. It uses camelCase attributes (className, onClick), requires one parent or fragment, and embeds JavaScript expressions in { }. It is compiled away at build time — not interpreted in the browser.

Q2. Function component vs class component — when would you still see classes?

Function components with hooks are the standard. Classes remain in legacy codebases and for error boundaries (still class-only). New code should use functions; know classes for maintenance and interviews about lifecycle mapping (componentDidMount → useEffect(..., [])).

Q3. What is the virtual DOM and does React always touch the real DOM?

React builds an in-memory element tree (virtual DOM). On update it reconciles the new tree with the previous, computes minimal changes, and applies them in the commit phase. React batches DOM updates; not every state change causes immediate DOM writes — it schedules a render first.

Q4. Why are keys important in lists?

Keys identify which items changed, moved, or were removed. Stable unique keys (usually IDs) preserve component state across reorders. Index keys break when list order changes — inputs retain wrong values and performance suffers.

Q5. Controlled vs uncontrolled components?

Controlled: React state drives the value (value + onChange). Uncontrolled: DOM holds state; read via ref. Controlled gives validation and single source of truth; uncontrolled is simpler for one-off forms or file inputs.

Q6. What is prop drilling and how do you avoid it?

Passing props through many intermediate layers. Fixes: colocate state, composition (children), Context for truly global low-churn data, or a state library. Don't reach for Context for frequently changing data — it re-renders all consumers.

Q7. What are synthetic events?

React's cross-browser wrapper around native events, using delegation at the root container. API resembles DOM events but is normalized. In React 17+, the root is the render container, not document.

Q8. Can you call hooks conditionally?

No (except use in React 19 for promises/context in specific patterns). Hooks must run in the same order every render. Conditional logic belongs inside the hook or in early returns after all hooks are called.

Hooks

Q9. Explain useEffect — when should you use it vs not use it?

Use for synchronizing with external systems: subscriptions, timers, manual DOM APIs, third-party widgets, logging. Don't use for: deriving display data from props/state (compute in render), handling user events (use handlers), or caching without external deps (use useMemo). Always consider cleanup and race conditions for async work.

Q10. What goes in the useEffect dependency array?

Every value from the component scope that the effect reads and that can change between renders: props, state, functions unless stable via useCallback. Omitting deps causes stale data; lying about deps causes bugs. Use eslint-plugin-react-hooks exhaustive-deps.

Q11. useEffect vs useLayoutEffect?

useEffect runs after paint (async, non-blocking). useLayoutEffect runs after DOM update but before browser paint — use for measurements, scroll position, focus that must happen before user sees frame. Avoid layout effects for data fetching.

Q12. What is a stale closure in React?

A callback or effect capturing old state/props from a previous render. Common in effects missing deps or event handlers registered once. Fix: update deps, use functional state updates, or store latest value in a ref.

Q13. useState vs useReducer — when prefer reducer?

Reducer when next state depends on complex logic, multiple sub-values update together, or you want explicit action types for debugging/testing. useState suffices for simple independent values.

Q14. What is useRef for?

(1) DOM element access, (2) mutable value persisting across renders without triggering re-render, (3) storing previous props/state, (4) holding timer/subscription IDs. Changing .current does not re-render.

Q15. How does useContext cause re-renders?

When Provider's value changes (reference equality), all consuming components re-render, even if they use only part of the value. Mitigate: split contexts, memoize value with useMemo, or use selectors via external store (useSyncExternalStore).

Q16. useMemo vs useCallback — difference and misuse?

useMemo caches a computed value; useCallback caches a function reference. Both help when referential equality prevents child re-renders or stabilizes effect deps. Misuse: wrapping cheap operations — adds overhead without benefit. Profile before optimizing.

Q17. What is useSyncExternalStore?

Hook for subscribing to external stores safely during concurrent rendering — prevents "tearing" (UI showing mixed versions). Used by Redux and Zustand integrations. You provide subscribe, getSnapshot, and optional getServerSnapshot.

Q18. Explain useTransition and useDeferredValue.

Both mark work as non-urgent. useTransition wraps state updates (startTransition) — returns isPending. useDeferredValue defers updating a derived value (e.g. search results while input stays instant). Keeps UI responsive under heavy renders.

Q19. How do custom hooks work?

JavaScript functions calling other hooks, named use*. They share stateful logic across components — not state itself (each call site gets its own state). Composable, testable with renderHook.

State & Data

Q20. Server state vs client state?

Server state: remote, async, shared, can become stale — cache with React Query/SWR. Client state: UI-local, synchronous — useState, Context, Zustand, Redux. Don't duplicate server data in Redux if React Query already caches it.

Q21. Why prefer React Query over useEffect fetch?

Built-in caching, deduplication, background refetch, stale-while-revalidate, retry, pagination helpers, devtools, and mutation/invalidation patterns. Raw useEffect requires reinventing race handling, cache, and loading states.

Q22. When would you still use Redux?

Complex client-side workflows, shared mutable UI state across many features, middleware needs (analytics, audit), time-travel debugging, or teams with established Redux patterns. For most server data, React Query is simpler.

Q23. How does React Query invalidation work?

After mutation, call queryClient.invalidateQueries({ queryKey: ['posts'] }). Marks matching queries stale and refetches active ones. Use hierarchical keys: ['posts'], ['posts', id].

Q24. Optimistic updates — how implement with React Query?

In onMutate, cancel outgoing refetches, snapshot previous cache, update cache optimistically. On error, rollback in onError. On settle, invalidateQueries for truth. UX feels instant while server confirms.

Q25. React Hook Form + Zod — why this combo?

RHF minimizes re-renders via uncontrolled inputs and refs. Zod provides schema validation with TypeScript inference. zodResolver connects them — single source of truth for rules and types. Scale better than hand-rolled validation.

Q26. What is lifting state up?

Move shared state to the closest common ancestor of components that need it. Pass state and setters down as props. Alternative to global store when scope is limited.

Q27. Immutability — why does React care?

React compares state by reference for bail-out optimizations and relies on new references to detect changes. Mutating state in place may skip re-renders or cause subtle bugs. Always create new objects/arrays for updates.

Rendering & Performance

Q28. What happens when setState is called?

React schedules a re-render of the component and typically its children. In React 18, updates batch across event handlers, promises, and timeouts. Render phase computes new UI; commit phase updates DOM and runs effects.

Q29. What is reconciliation?

Algorithm comparing new element tree with previous. Same component type: update props in place. Different type: unmount old, mount new. Lists use keys to match identity. Goal: minimal DOM operations.

Q30. When does React.memo help?

When a component re-renders often with same props and render is expensive. Shallow-compares props — useless if parent passes new object/function references every render unless those are stabilized.

Q31. How do you debug unnecessary re-renders?

React DevTools Profiler (highlight updates), why-did-you-render, check Context providers wrapping too much, unstable inline props, state placed too high in tree. Fix architecture before sprinkling memo.

Q32. Code splitting in React?

React.lazy(() => import('./Page')) + Suspense fallback. Route-based splitting via router or framework (Next.js dynamic import). Reduces initial bundle, improves TTI.

Q33. What is Suspense?

Declarative boundary showing fallback while children aren't ready — lazy components or data (via frameworks/libraries throwing promises). Enables coordinated loading states and streaming SSR.

Q34. Explain Concurrent React in one minute.

React can pause low-priority renders, keep UI responsive for user input, and resume later. Features: transitions, deferred values, Suspense. Requires createRoot. Scheduler assigns priorities via lanes.

Architecture & Patterns

Q35. Error boundaries — what catches what?

Class components with getDerivedStateFromError / componentDidCatch catch render errors in children. They do NOT catch: event handler errors, async code, SSR errors, or errors in the boundary itself. Use try/catch for events; global handler for logging.

Q36. Composition vs inheritance in React?

React favors composition: pass components as props/children, render props, hooks. Inheritance across component classes is an anti-pattern — limits flexibility and reuse.

Q37. HOC vs render props vs hooks?

All share cross-cutting logic. HOCs wrap components (wrapper hell, ref forwarding pain). Render props invert control via function child. Hooks replace both for most cases with cleaner trees and TypeScript. Know HOCs for legacy code.

Q38. Micro-frontends — key challenges?

Shared dependency versions (React duplication breaks hooks), consistent routing, CSS isolation, cross-app communication, independent deploys vs UX cohesion, performance of loading multiple bundles. Module Federation addresses some sharing concerns.

Q39. How would you structure a large React app?

Feature folders, shared UI kit, API layer with React Query, route-based code splitting, colocated tests, env config, design tokens. Avoid deep prop drilling; don't globalize state prematurely. Monorepo optional for multi-app orgs.

Q40. React Native vs React web — what's shared?

Hooks, component mental model, many libraries (with RN variants). Different primitives (View/Text vs HTML), styling (StyleSheet, no CSS cascade), navigation (React Navigation), native bridge/JSI for platform APIs.

Next.js, SSR & RSC

Q41. CSR vs SSR vs SSG — trade-offs?

CSR: fast subsequent nav, slow FCP, poor SEO without extra work. SSR: fresh HTML per request, better SEO/FCP, server cost. SSG: fastest static delivery, rebuild for changes. Choose per page/data freshness needs.

Q42. What is hydration and what causes mismatches?

Client JS attaches to server-rendered HTML and makes it interactive. Mismatch when server HTML ≠ client first render: random IDs, dates, browser-only APIs, invalid HTML nesting, extensions modifying DOM. React may discard server HTML and client-render.

Q43. What are React Server Components?

Components running only on server — can access DB/filesystem directly, zero client bundle for their logic. Cannot use hooks or browser APIs. Pass serializable props to Client Components. Reduce JS and improve data colocation.

Q44. 'use client' vs Server Component default in App Router?

Server Components are default — no directive needed. Add 'use client' at top of files needing hooks, state, effects, browser APIs. Client components can import server components as children but not vice versa (except as props/slots).

Q45. Server Actions — what problem do they solve?

Colocate server mutations callable from forms without manual API routes. Progressive enhancement: work without JS. React 19 integrates pending states via Actions and useActionState.

Q46. Protected routes in React SPA?

Route wrapper checks auth (context/store), redirects unauthenticated users to login, preserves intended URL. For SSR, validate session cookie in loader/middleware before rendering protected data.

Q47. Where to store JWT — localStorage vs cookie vs memory?

localStorage: XSS-vulnerable. httpOnly Secure SameSite cookie: CSRF considerations but not readable by JS. Memory + refresh token in httpOnly cookie: common SPA pattern. No perfect answer — mitigate XSS and CSRF together.

Testing, Security & A11y

Q48. React Testing Library philosophy?

Test how users interact — query by accessible roles/labels, not implementation details. Avoid testing state or private methods. Prefer integration tests over shallow unit tests of every component.

Q49. How to test async data fetching?

MSW to mock HTTP; wrap in QueryClientProvider; use findBy* or waitFor. Test loading, success, and error UI. Don't mock fetch implementation details unless necessary.

Q50. XSS risks in React?

React escapes text in JSX. Risks: dangerouslySetInnerHTML, user-controlled href with javascript:, embedding untrusted JSON in scripts. Sanitize HTML; validate URLs; use CSP headers.

Q51. Accessibility essentials for modals?

Focus trap inside dialog, return focus on close, role="dialog" + aria-modal="true", label with aria-labelledby, close on Escape, prevent background interaction. Prefer native <dialog> where supported.

Q52. What are Core Web Vitals for React SPAs?

LCP (load hero content fast — SSR, image optimization), INP (keep main thread free — code split, defer work), CLS (reserve layout space). Measure with web-vitals library and Lighthouse; fix real user data in RUM.

Advanced & React 19

Q53. What is Fiber?

React's internal linked-node architecture representing work units. Enables incremental rendering, prioritization, pausing/resuming, and double-buffering (current vs work-in-progress tree). Explains concurrent features and effect flushing order.

Q54. Why does Strict Mode double-invoke effects in dev?

To surface side effects that aren't properly cleaned up — simulates mount/unmount/remount. Production runs once. Ensures subscriptions and listeners don't leak.

Q55. React 19 use hook — how differs from useContext?

use can read Context and unwrap Promises during render when wrapped in Suspense. Can be called conditionally after early returns in some patterns. Integrates with streaming and async Server Components.

Q56. useActionState vs manual form state?

useActionState(action, initialState) returns [state, formAction, isPending]. React handles pending state for Server Actions/async form handlers — less boilerplate than manual useState for submitting/errors.

Q57. useOptimistic — use case?

Show optimistic UI (e.g. message appeared) while async mutation runs; reverts if server fails. Built-in pattern replacing hand-rolled optimistic state + rollback.

Q58. React Compiler — will we stop using useMemo?

Compiler auto-memoizes at build time when safe. Goal: reduce manual optimization. Until universally adopted, still know when referential stability matters and profile hot paths.

Q59. How would you migrate class components to hooks?

Incremental: one component at a time. Map lifecycle to effects, state to useState/useReducer, refs to useRef, context to useContext. Keep error boundaries as classes until a library alternative exists. Add tests before refactor.

Q60. Design a scalable data layer for a dashboard app.

React Query for server data with normalized query keys per entity. URL state for filters (shareable). Local UI state in components. WebSocket updates via Query cache invalidation or direct cache writes. Auth in Context + httpOnly refresh. RTK only if complex client workflows emerge. Instrument with error boundaries and query devtools.
