Basics

What is Next.js and how is it different from React?

Next.js is a React framework — it adds file-based routing, SSR/SSG/ISR, API routes, Server Components, optimizations (image, font), and deployment tooling. React is the UI library; Next.js is the full-stack framework built on React.

App Router vs Pages Router?

App Router (app/) is the modern default — Server Components, layouts, streaming, Server Actions, nested routing. Pages Router (pages/) uses getStaticProps/getServerSideProps — still supported but legacy. New projects use App Router.

What is the purpose of layout.tsx?

Shared UI wrapper that persists across navigations within its segment — nav, sidebar, providers. Child pages render in the {children} slot. Root layout is required and wraps the entire app.

Server & Client Components

When do you use "use client"?

When the component needs useState, useEffect, event handlers, browser APIs, or third-party libs that use hooks. Default is Server Component — no directive needed. Push "use client" to leaf components to minimize client JS bundle.

Can Server Components import Client Components?

Yes — Server can import and render Client Components, passing serializable props. Client Components cannot import Server Components directly — pass Server output as children prop instead (composition pattern).

Can you fetch data in Client Components?

Yes via useEffect/fetch or React Query — but data hits client bundle path, no direct DB access, worse for SEO. Prefer async Server Components for initial data; Client + React Query for interactive refetching.

Caching

Explain Next.js caching layers.

Request memoization (dedupe same fetch in one render), Data cache (fetch results persisted), Full Route cache (rendered HTML/RSC at build/revalidate), Router cache (client prefetched segments). Opt out with cache: 'no-store' or dynamic = 'force-dynamic'.

Difference between revalidatePath and revalidateTag?

revalidatePath('/posts') — invalidate specific route's cache. revalidateTag('products') — invalidate all fetch calls tagged with that tag — finer-grained for shared data across routes.

How do you make a route fully dynamic?

export const dynamic = 'force-dynamic' or use fetch(url, { cache: 'no-store' } or read cookies/headers in Server Component (automatically dynamic). Each request renders fresh.

SSR, SSG & ISR

SSR vs SSG vs ISR in Next.js App Router?

SSG: static at build — default static fetch. SSR: render per request — no-store or dynamic. ISR: static + background revalidate — next: { revalidate: N }. Choose based on freshness vs performance trade-off.

What causes hydration errors?

Server HTML doesn't match client's first render — Date.now(), random IDs, browser-only APIs in initial render, invalid HTML nesting. Fix: render consistently, defer browser code to useEffect, use suppressHydrationWarning only for known mismatches like timestamps.

Server Actions & API

What are Server Actions?

Async functions marked "use server" that run on server — callable from forms or Client Components. Handle mutations without building API routes. Progressive enhancement — forms work without JS. Revalidate cache after mutations.

Server Actions vs Route Handlers?

Server Actions: form mutations, typed functions, integrated with RSC cache revalidation — not a public HTTP API. Route Handlers: REST/webhook endpoints at app/api/*/route.ts — external clients, mobile apps, third-party integrations.

Auth & Middleware

How does Next.js middleware work?

Runs on Edge before request completes — auth checks, redirects, rewrites. middleware.ts at root with matcher config. Can read cookies/headers, return NextResponse.redirect. Fast but limited Node APIs.

Best auth pattern for Next.js App Router?

Auth.js (NextAuth v5) with session in httpOnly cookie — works with middleware, Server Components (await auth()), and Server Actions. Avoid localStorage tokens for SSR pages — causes flash and XSS risk.

Advanced

Edge runtime vs Node runtime?

Edge: middleware, low latency globally, limited APIs (no fs, native modules). Node: full Node.js APIs, DB drivers, heavy computation — default for Server Components and Route Handlers unless export const runtime = 'edge'.

How do you deploy Next.js in Docker?

output: 'standalone' in next.config — produces minimal server.js + traced deps. Multi-stage Docker build: install, build, copy standalone + static + public. Run node server.js. Set env vars at runtime.

What is Partial Prerendering (PPR)?

Static HTML shell at build with dynamic holes streamed in — combines SSG speed with personalized dynamic content. Suspense boundaries mark static vs dynamic regions. Next.js experimental feature for optimal Core Web Vitals.
