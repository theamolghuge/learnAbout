1. What is Next.js?

Next.js is a React framework for production — routing, rendering (SSR/SSG/ISR), API routes, optimizations, and deployment. Built on React Server Components in the App Router era.

vs CRA/Vite SPANext.js adds
Client-only renderSSR, SSG, ISR, RSC on server
Manual routingFile-system App Router
Manual API serverRoute Handlers, Server Actions
Manual SEOMetadata API, streaming HTML

3. Server & Client Components

Server Component (default)Client Component
DirectiveNone"use client"
Runs onServer onlyServer + client (hydrates)
HooksNo useState/useEffectAll hooks OK
Browser APIsNoYes
DB/API directYesVia fetch/actions
JS to clientZero for RSC payloadFull component JS
// Server Component (default) — app/users/page.tsx
async function UsersPage() {
  const users = await db.user.findMany();  // direct DB OK
  return <UserList users={users} />;
}

// Client Component — components/Counter.tsx
"use client";
export function Counter() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}

Rule: push Client Components down the tree — keep leaves interactive, keep pages/layouts as Server Components when possible.

4. Data Fetching

// Async Server Component
async function ProductPage({ params }: { params: { id: string } }) {
  const product = await fetch(`https://api.example.com/products/${params.id}`, {
    next: { revalidate: 3600 },  // ISR — revalidate every hour
  }).then(r => r.json());

  return <ProductDetails product={product} />;
}

// Client-side (interactive UI, polling)
"use client";
function Dashboard() {
  const { data } = useQuery({ queryKey: ["stats"], queryFn: fetchStats });
  return <Stats data={data} />;
}

When to fetch where: Server Component for initial data, SEO, secrets. Client + React Query for user-driven refetch, optimistic updates, realtime.

// Static — cached at build
fetch(url, { cache: 'force-cache' });  // default

// Dynamic — every request
fetch(url, { cache: 'no-store' });

// ISR — revalidate after N seconds
fetch(url, { next: { revalidate: 60 } });

// Route segment config
export const dynamic = 'force-dynamic';
export const revalidate = 3600;

Hydration

Server sends HTML + RSC payload. Client hydrates interactive Client Components. Mismatch → hydration error. Fix: same server/client output, browser-only code in useEffect, suppressHydrationWarning sparingly for timestamps.

7. Server Actions

// app/actions.ts
"use server";

export async function createPost(formData: FormData) {
  const title = formData.get("title") as string;
  await db.post.create({ data: { title } });
  revalidatePath("/posts");
}

// app/posts/new/page.tsx
import { createPost } from "../actions";

export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" />
      <button type="submit">Create</button>
    </form>
  );
}
  • Progressive enhancement — works without JS
  • Call from Client Components too
  • Validate with Zod inside action
  • Use revalidatePath / revalidateTag after mutations

8. Route Handlers

// app/api/users/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(request: NextRequest) {
  const users = await db.user.findMany();
  return NextResponse.json(users);
}

export async function POST(request: NextRequest) {
  const body = await request.json();
  const user = await db.user.create({ data: body });
  return NextResponse.json(user, { status: 201 });
}

Route Handlers replace Pages Router pages/api/*. Use for webhooks, REST APIs, when Server Actions aren't enough.

9. Middleware

// middleware.ts — runs on Edge
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const token = request.cookies.get("session")?.value;
  if (!token && request.nextUrl.pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/login", request.url));
  }
  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/api/:path*"],
};

Edge runtime — fast, limited Node APIs. Auth checks, redirects, geo, A/B tests, rewrite URLs.
