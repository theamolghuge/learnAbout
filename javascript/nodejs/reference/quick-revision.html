Tier 1 — Must Know

TopicKey points
Event Loop6 phases: timers → pending → idle → poll → check → close. Microtasks (Promises) between phases. nextTick before microtasks.
ModulesCJS: require/module.exports (sync, cached). ESM: import/export ("type":"module"). Dynamic import is async.
Async/Awaitasync always returns Promise. try/catch around await. unhandledRejection crashes in prod.
StreamsReadable, Writable, Duplex, Transform. Backpressure: pause on write() false, resume on drain. Use pipeline().
ExpressMiddleware chain (req, res, next). Error middleware: 4 args, last. Order: security → parser → auth → routes → 404 → errors.
RESTNouns not verbs. 200/201/204/400/401/403/404/409/422/429/500. GET/PUT/DELETE idempotent. POST is not.
Authbcrypt cost 10-12. JWT: short access + refresh rotation. httpOnly secure cookies. Never store secrets in JWT payload.
SQLIndexes speed reads, slow writes. Transactions for multi-step writes. N+1 → JOIN or eager load. Pool connections.
RedisCache-aside: check cache → miss → DB → set cache. TTL + invalidation on write. Shared across instances.
SecurityHelmet, CORS whitelist, rate limit, validate input (Zod), parameterized queries, npm audit, no secrets in code.

Tier 2 — Senior Level

TopicKey points
Cluster vs WorkersCluster: fork processes, I/O-bound HTTP. Workers: threads, CPU-bound tasks. Cluster = isolation; Workers = shared memory.
Prisma$transaction for atomic ops. include for eager loading. Migrations for schema changes. Connection pool limits.
MongoDBDocuments, flexible schema, $lookup joins, aggregation pipeline. Embed one-to-few, reference one-to-many.
QueuesBull/BullMQ (Redis), SQS (managed). At-least-once + idempotent consumers. Dead-letter queues for failures.
WebSocketsFull-duplex persistent connection. Use ws library. SSE for server→client only (simpler).
GraphQLSingle endpoint, client picks fields. N+1 → DataLoader. Complexity limits prevent expensive queries.
gRPCHTTP/2 + Protobuf. Internal microservices. 4 call types including bidi streaming. grpc-web for browsers.
DockerMulti-stage builds. Non-root user. HEALTHCHECK. .dockerignore. Immutable images per release.
NginxReverse proxy, SSL termination, load balance, static files, rate limit. proxy_set_header X-Forwarded-*.
OpenAPIContract-first API spec. Swagger UI for docs. Codegen for clients. Validate requests against schema.
12-FactorConfig in env. Stateless processes. Logs to stdout. Graceful shutdown on SIGTERM. Dev/prod parity.
VersioningURL path (/v1/) most common. Only version breaking changes. Sunset header for deprecation.
SagaDistributed txns with compensating actions. Orchestration (central) vs choreography (events).
OutboxWrite event + business data in same DB txn. Relay publishes to queue. Avoids dual-write problem.
CQRSSeparate write model (commands) from read model (queries). Eventual consistency. Event sync between sides.

Tier 3 — Staff / Deep

TopicKey points
KubernetesPod → Deployment (replicas, rolling update) → Service (stable IP). ConfigMap/Secret for config. HPA for auto-scale.
KafkaTopics partitioned. Consumer groups: 1 consumer per partition. Offsets track progress. Idempotent producers.
Performanceclinic.js profiling. Don't block event loop. Stream large data. Connection pooling. Watch memory leaks.
AWSECS/Fargate, RDS, ElastiCache, ALB, SQS, Secrets Manager, CloudWatch. IAM roles for tasks, not keys.
ObservabilityStructured JSON logs (pino). Correlation/request IDs. OpenTelemetry traces. Metrics: latency, error rate, throughput.
CAPPick 2 of Consistency, Availability, Partition tolerance. CP (banking) vs AP (social feeds). Eventual consistency.
Rate LimitingToken bucket (burst ok). Sliding window (precise). Redis-backed for distributed. 429 + Retry-After.
Circuit BreakerClosed → Open (fail fast) → Half-Open (test). opossum library. + retries with backoff/jitter.
Event SourcingStore events not state. Replay to rebuild. Pairs with CQRS. Kafka as event store.
Service MeshIstio/Linkerd: mTLS, retries, observability between pods. Sidecar proxy pattern.

One-Liner Reminders

  • Event loop blocked? → worker_threads or separate service
  • Large file? → streams, never readFile entire file
  • Duplicate webhook? → idempotency key
  • DB + queue write? → transactional outbox
  • Multi-service txn? → saga with compensation
  • Cache stale? → invalidate on write, not just TTL
  • Deploy? → SIGTERM handler, drain connections, then exit
  • Secret leaked? → rotate immediately, never commit .env
