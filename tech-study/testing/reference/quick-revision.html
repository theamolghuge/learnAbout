Tier 1 — Must Master

TopicOne-liner
Test pyramidMany unit tests · some integration · few E2E
@BeforeEach/@AfterEachFresh state per test
assertThrowsCleaner than manual try/catch + fail()
@MockFake dependency, stub with when/thenReturn
@InjectMocksReal class under test, mocks wired in
verify(mock).method()Behavior verification — was it called?
@WebMvcTest + MockMvcWeb layer only · mock services with @MockBean

TopicOne-liner

30-second answers

when/thenReturn vs verify?
Stub the input (when) vs assert the interaction happened (verify) — setup vs check.

Why not @SpringBootTest everywhere?
Full context startup is slow — reserve it for a handful of true integration flows.

Why Testcontainers over H2?
Real DB engine — catches dialect-specific bugs H2 silently allows.

Implement from memory

  • Mockito unit test for a Service: mock repository, verify a downstream call happens
  • @WebMvcTest for a GET and a validation-failing POST (200 + 400 cases)
  • @DataJpaTest verifying a custom findBy query
  • Explain, out loud, when you'd reach for each of the four test types above
