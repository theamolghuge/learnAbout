OOP

What is the difference between overloading and overriding?

Overloading is having multiple methods with the same name but different parameter lists in the same class — resolved at compile time based on argument types. Overriding is a subclass redefining a superclass method with the same signature — resolved at runtime based on the actual object type (dynamic dispatch).

Why must you override hashCode() whenever you override equals()?

The contract requires that equal objects produce equal hash codes. If you only override equals(), two "equal" objects can land in different HashMap buckets — a HashSet.contains() or HashMap.get() call will silently fail to find an object that should be considered present.

What is the difference between this and super?

this refers to the current instance — used to disambiguate fields from parameters or to chain constructors (this(...)). super refers to the immediate parent class — used to call a parent constructor (super(...), must be first line) or an overridden parent method (super.method()).

Why is String immutable in Java?

Security (can't be altered after being passed to trusted code like a filename or SQL string), safety for use as a HashMap key (hash code can be cached once), thread-safety (shareable across threads with no locking), and to enable the string pool, which saves memory by reusing literal instances.

Can a constructor be private? Why would you do that?

Yes — commonly used for the Singleton pattern (control the one instance via a static factory method) or utility classes with only static members (prevent instantiation entirely).

Interfaces & Abstract Classes

When would you choose an abstract class over an interface?

When several closely related classes need to share actual field state or a chunk of concrete implementation, and single inheritance is acceptable — e.g. a base Shape class holding a common color field and a shared describe() method, with each subclass only implementing area().

What are default methods on interfaces for?

Introduced in Java 8 to let interfaces evolve without breaking every existing implementer — e.g. List.sort() was added as a default method so old List implementations kept compiling. They also let an interface provide reusable behavior on top of its abstract methods.

Can a class implement two interfaces that both have the same default method?

It's a compile error unless the class explicitly overrides the method and resolves the conflict — e.g. by calling InterfaceA.super.method() to pick one, or providing its own logic.

Exception Handling

Checked vs unchecked exceptions — which should a Spring service layer throw?

Checked exceptions must be caught or declared (throws); unchecked (RuntimeException subclasses) don't require that. Most Spring codebases favor unchecked exceptions for business errors (e.g. UserNotFoundException extends RuntimeException) — it keeps service method signatures clean and lets a global @ControllerAdvice handle them centrally instead of forcing every caller to catch.

Does code in a finally block always run?

Almost always — even if the try or catch block returns, or throws a new exception. The only exceptions: the JVM exits (System.exit()) or the thread is killed while inside the try block.

What does try-with-resources do, and what's required for a class to use it?

It automatically calls close() on the resource once the block exits, even on exception — equivalent to an implicit finally. The resource must implement AutoCloseable. Common in JDBC (Connection, Statement, ResultSet all implement it).

What happens if an exception is thrown in both the try block and the finally block?

The exception from finally wins and propagates; the original exception from try is suppressed (though it's still retrievable via getSuppressed() if using try-with-resources).

Collections

Walk through what happens internally when you call hashMap.put("a", 1).

Java computes "a".hashCode(), spreads/masks it to pick a bucket index in the internal array. If the bucket is empty, a new entry (node) is placed there. If occupied (collision), Java walks the chain using equals() to check for an existing matching key — replacing its value if found, else appending (as a linked list, or a red-black tree if the chain exceeds 8 entries). If the map is now over 75% full (load factor), the whole table doubles in size and rehashes.

ArrayList vs LinkedList — which do you default to and why?

ArrayList by default — O(1) random access and better cache locality (contiguous array) make it faster for the vast majority of use cases including iteration and appending. LinkedList only wins for frequent insert/delete at the head or a known middle node, which is rare; ArrayDeque is usually a better choice than LinkedList even for queue/stack use.

How does a HashSet guarantee no duplicates?

It's backed internally by a HashMap where each element is stored as a key (with a shared dummy value). add() is really map.put(element, DUMMY) — if hashCode()+equals() find an existing equal key, the "add" is a no-op and returns false.

What breaks if you put a mutable object into a HashSet and then mutate a field its hashCode() depends on?

The object becomes "lost" — it's still physically in some bucket, but future lookups recompute the hash from its new state and search the wrong bucket, so contains() returns false even though the object is in the set. Prefer immutable keys/elements.

Difference between Comparable and Comparator?

Comparable is implemented by the class itself to define one natural ordering (compareTo). Comparator is a separate object (often a lambda) passed in to define an ordering externally — useful when you need multiple different sort orders for the same class without modifying it.

Is a HashMap thread-safe? What would you use instead in a multithreaded Spring service?

No — concurrent modification can corrupt its internal structure or cause an infinite loop in older JVMs. Use ConcurrentHashMap, which locks at a fine granularity (per bucket/segment) instead of the whole map, giving much better throughput than wrapping a HashMap with Collections.synchronizedMap().

Generics

What is type erasure and why does it matter?

Generic type information exists only at compile time for type checking; the compiler erases it and inserts casts, so at runtime List<String> and List<Integer> are both just List. It matters because you can't do new T(), can't check instanceof List<String>, and can't overload methods that differ only by generic type parameter.

Explain PECS.

"Producer Extends, Consumer Super" — use <? extends T> for a structure you only read from (it produces T values for you), and <? super T> for one you only write to (it consumes T values from you). This maximizes API flexibility while staying type-safe.

Java 8+

Are streams lazy or eager? What does that mean in practice?

Lazy — intermediate operations (filter, map, sorted) just build a pipeline description and don't run anything. Nothing executes until a terminal operation (collect, forEach, reduce, count) is called, at which point the whole pipeline runs element-by-element in one pass. This also means a stream with no terminal operation does nothing at all.

Can you reuse a Java Stream after calling a terminal operation on it?

No — a stream is consumed exactly once. Calling another operation on an already-consumed stream throws IllegalStateException. You'd need to create a fresh stream from the source collection.

What problem does Optional solve, and how should it NOT be used?

It makes "this might not have a value" explicit in a method's return type, forcing the caller to handle absence instead of risking a NullPointerException from a returned null. It should not be used as a field type, constructor/method parameter, or inside a collection — it's designed specifically for return types.

What's the difference between map() and flatMap() on a stream?

map() transforms each element one-to-one, possibly producing a stream of streams if the mapper returns a collection. flatMap() transforms each element into a stream and then flattens all of them into a single stream — used when each input maps to zero or more outputs, e.g. turning a List<List<String>> into a flat List<String>.

Concurrency

What is a race condition, and how does synchronized prevent it?

A race condition happens when multiple threads read and write shared state without coordination, and the outcome depends on timing — e.g. count++ is really read-modify-write, and two interleaved threads can both read the same old value and lose an update. synchronized makes a method or block acquire the object's intrinsic lock, so only one thread can execute it at a time, making the compound operation atomic.

When is volatile enough, and when do you need synchronized instead?

volatile only guarantees visibility — every thread sees the latest write, with no caching/reordering. It does NOT make compound operations atomic. Use it for simple flags (e.g. a shutdown signal read by multiple threads). Use synchronized (or an atomic type) when the operation is read-modify-write or involves multiple related fields that must change together.

Why prefer ExecutorService over creating raw Thread objects?

Raw threads are expensive to create and give you no control over concurrency limits — spawning one per task can exhaust memory/OS resources under load. An ExecutorService manages a bounded pool of reusable threads, provides backpressure via task queues, and gives you Future/CompletableFuture for results and composition — this is effectively how Spring/Tomcat handle incoming requests under the hood.

How does ConcurrentHashMap achieve better concurrency than a synchronized HashMap?

A synchronized HashMap locks the entire map for every operation — only one thread can touch it at all, at any time. ConcurrentHashMap locks at a much finer granularity (per bucket, using CAS operations where possible), so unrelated reads/writes to different buckets can proceed in parallel.

JVM

What's the difference between JDK, JRE, and JVM?

JVM executes bytecode and manages memory/GC. JRE is the JVM plus the standard class libraries needed to run compiled Java programs. JDK is the JRE plus development tools (compiler javac, debugger, etc.) — what you install to build software, as opposed to just run it.

Explain generational garbage collection at a high level.

Most objects die young, so the heap is split into a Young generation (frequently, cheaply collected) and an Old generation (rarely collected, more expensive). Objects start in Young (Eden space); survivors get copied between Survivor spaces and eventually promoted to Old once they've lived through enough collection cycles. This generational split avoids repeatedly scanning long-lived objects.

What makes an object eligible for garbage collection?

When it's no longer reachable from any GC root — thread stacks, static fields, active local variables. There's no manual free(); the collector periodically traces reachability from roots and reclaims anything not reached. Circular references between two otherwise-unreachable objects are still collected, unlike simple reference counting.

Misc

What is a Java record, and when would you use one?

A record (Java 16+) is a compact, immutable data carrier — the compiler auto-generates the constructor, accessors, equals(), hashCode(), and toString() from its declared fields. Ideal for DTOs, value objects, and API request/response shapes where you just need to carry data with no extra behavior.

Why is Integer a = 127; Integer b = 127; a == b true, but the same with 200 is false?

Java caches boxed Integer values from -128 to 127 (the "Integer cache") for autoboxing, so both variables point to the same cached object in that range. Outside the range, autoboxing creates new distinct objects, so == (reference comparison) returns false. Always use .equals() for wrapper value comparison.
