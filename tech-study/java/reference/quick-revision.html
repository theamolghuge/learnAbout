Quick Revision Guide

Last-minute scan before a backend interview. Full detail & learning order in Java Notes.

Tier 1 — Must Master

TopicOne-liner
OOP pillarsEncapsulation, Inheritance, Polymorphism, Abstraction
Overload vs OverrideOverload = compile-time, same class, diff params · Override = runtime, subclass, same signature
equals/hashCodeOverride both together or break HashMap/HashSet lookup
Interface vs abstract classInterface = contract, multi-implement, no state · Abstract = shared state + impl, single extend
Checked vs uncheckedChecked = must handle/declare · Unchecked = RuntimeException, preferred in Spring services
try-with-resourcesAuto-closes AutoCloseable · used for Connection/Statement/ResultSet
ArrayList vs LinkedListArray = O(1) get, default choice · Linked = O(1) head/tail insert only
HashMap internalshash → bucket → chain (tree if >8) → resize at 75% load factor
Comparable vs ComparatorComparable = in-class, one order · Comparator = external, many orders
StreamsLazy, one-time-use pipeline · nothing runs until a terminal op
OptionalReturn type only — never field/param/collection
synchronizedVisibility + atomicity via intrinsic lock — for compound ops
volatileVisibility only — for simple flags, not compound ops

Tier 2 — Advanced

TopicOne-liner
Type erasureGenerics vanish at runtime · no new T(), no generic instanceof
PECSProducer Extends, Consumer Super
ExecutorServiceManaged thread pool — don't spawn raw Threads in real apps
ConcurrentHashMapBucket-level locking, not whole-map
CompletableFuture.thenApply().thenCompose().exceptionally() async pipelines
Integer cache-128..127 cached — always use .equals() for wrapper compare
RecordImmutable data carrier — auto ctor/equals/hashCode/toString
java.timeImmutable, thread-safe · store Instant UTC, convert at the edge

Tier 3 — Discussion (skim)

TopicOne-liner
JDK / JRE / JVMJDK = build tools + JRE · JRE = JVM + libs · JVM = runs bytecode
Generational GCYoung (Eden+Survivor, frequent) → promoted to Old (rare, expensive)
GC eligibilityUnreachable from GC roots (stacks, statics) — no manual free()
Class loadingLazy, delegation hierarchy: Bootstrap → Platform → Application

String pool output tricks

String s1 = "abc";
String s2 = "abc";
s1 == s2;                      // true  — pooled literal
new String("abc") == s1;       // false — new heap object

Integer a = 127, b = 127;
a == b;                        // true  — Integer cache
Integer c = 200, d = 200;
c == d;                        // false — outside cache

HashMap.put() — 30-second answer

Hash the key → mask to bucket index → empty? insert : walk chain with equals() → found? replace value : append (treeify if chain > 8) → over 75% full? double + rehash.

Implement from memory

  • Custom equals()/hashCode() for a class with 2-3 fields
  • Singleton with private constructor + static factory
  • group-by with streams (Collectors.groupingBy)
  • Thread-safe counter: synchronized vs AtomicInteger
  • Custom unchecked exception + where it'd be thrown
