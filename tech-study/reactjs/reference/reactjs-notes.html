3. State & Immutability

const [count, setCount] = useState(0);
setCount(c => c + 1);  // functional update — safe when prev matters

// IMMUTABILITY — always new reference
setUser({ ...user, name: "Ada" });
setItems([...items, newItem]);
setItems(items.filter(i => i.id !== id));
setNested({
  ...state,
  profile: { ...state.profile, email: "new@x.com" }
});

Why immutability: React uses reference equality for bail-out. In-place mutation may skip re-render or cause stale UI. Enables time-travel debugging, predictable updates, and cheap change detection.

Lifting state up: siblings share state → move to closest common parent → pass props + callbacks down.

5. Hooks

Rules: top level only · React functions only · same order every render.

useState

const [state, setState] = useState(initialValue);
setState(newVal);
setState(prev => prev + 1);

useEffect ⭐ — most interviewed hook

useEffect(() => {
  const sub = subscribe(userId);
  document.title = `User ${userId}`;

  return () => sub.unsubscribe();  // cleanup
}, [userId]);

useEffect(() => { ... }, []);    // mount + unmount only
useEffect(() => { ... });        // every render — rarely correct
PatternDeps
Fetch on mount[]
Fetch when id changes[id]
Sync with prop[prop]
Event listener[handler] + cleanup removeListener

Common mistakes: missing deps, no cleanup (memory leaks), fetching without abort, infinite loops from setting state without condition.

useRef

const inputRef = useRef(null);
inputRef.current?.focus();       // DOM — no re-render

const prevId = useRef();
useEffect(() => { prevId.current = id; }, [id]);

useMemo & useCallback

const sorted = useMemo(() => expensiveSort(items), [items]);
const handleClick = useCallback(() => onSelect(id), [id, onSelect]);

Use when passing to React.memo children or deps of other hooks — not everywhere by default.

useContext

const ThemeContext = createContext("light");
const theme = useContext(ThemeContext);

useReducer (Tier 2)

const [state, dispatch] = useReducer(reducer, initialState);
dispatch({ type: "ADD", payload: item });

useLayoutEffect (Tier 2)

Runs synchronously after DOM mutations, before paint. Use for measuring DOM, preventing flicker. Prefer useEffect for most side effects.

Custom hooks ⭐

function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

function useLocalStorage(key, initial) {
  const [val, setVal] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initial;
  });
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(val));
  }, [key, val]);
  return [val, setVal];
}

Custom hooks share logic, not state — each call gets independent state.

8. Rendering, Re-rendering & Reconciliation ⭐

What triggers re-render?

  • useState / useReducer setter called
  • Parent re-renders (children re-render by default)
  • Context value changes (all consumers)
  • forceUpdate (legacy, avoid)

Render pipeline

  1. Render phase — call components, build new element tree (pure, can be interrupted in concurrent mode)
  2. Reconciliation — diff new vs old Virtual DOM
  3. Commit phase — apply DOM changes, run layout effects, run passive effects

Virtual DOM

Lightweight JS object tree representing UI. On state change, React builds new tree, diffs with previous, batches minimal DOM updates. Trade-off: JS diff cost vs fewer DOM operations — wins at scale with predictable patterns.

Reconciliation rules

  • Different element type → destroy subtree, rebuild
  • Same type → update props, recurse children
  • Lists → keys determine identity across renders

Error boundaries (class only)

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logError(error, info); }
  render() {
    return this.state.hasError ? <Fallback /> : this.props.children;
  }
}

Catch render errors — not event handlers, async, or SSR errors.

  • Automatic batching (React 18) — multiple setStates in async/promises batch to one render

  • Suspense — declarative loading states for lazy components and data

11. SSR, Hydration & React Server Components

ModeWhere rendersPros
CSRBrowserSimple SPA, rich interactivity
SSRServer → HTML → hydrate clientFast FCP, SEO
SSGBuild timeStatic pages, CDN cache
RSCServer components (no JS to client)Zero bundle for data fetching UI

Hydration

Client attaches event listeners and state to server HTML. Mismatch between server and client render → hydration error. Fix: useEffect for browser-only code, consistent data, avoid Date.now() / random in initial render.

React Server Components (RSC)

  • Run only on server — can access DB/filesystem directly
  • No hooks like useState/useEffect in Server Components
  • Client Components marked with "use client" — interactivity, hooks
  • Streaming — send HTML in chunks as ready (Suspense boundaries)

13. Security, Testing & Accessibility

React security

  • JSX auto-escapes — safe for strings; dangerous: dangerouslySetInnerHTML
  • Sanitize HTML (DOMPurify) if rendering rich text
  • Never store tokens in localStorage if XSS risk — prefer httpOnly cookies
  • Validate props, CSP headers, dependency audits

14. Fiber & React Internals

React Fiber

Linked list of fiber nodes — each represents a unit of work. Enables:

  • Incremental rendering — split work across frames
  • Prioritization — user input > transitions > offscreen
  • Pause/resume — don't block main thread on large trees
  • Concurrent features — Suspense, transitions

Render vs Commit phase

PhaseWorkInterruptible?
RenderCall components, diff — build effect listYes (concurrent)
CommitDOM updates, useLayoutEffect, useEffect scheduleNo — must be atomic

Scheduling & lanes

React 18 assigns update priority via lanes — sync updates (clicks) interrupt transitions. Scheduler package coordinates when to yield to browser.

16. Micro Frontends, Module Federation & Design Systems

Micro Frontends (MFE)

Split frontend into independently deployable apps — team autonomy, separate release cycles. Integration via:

  • Module Federation (Webpack 5) — runtime sharing of components/modules between apps
  • iframe / Web Components — strong isolation, harder UX integration
  • Single-SPA — orchestration layer for multiple frameworks
// Module Federation — host consumes remote
remotes: {
  shop: "shop@https://shop.example.com/remoteEntry.js",
}
// import('shop/ProductCard') at runtime

Design systems

  • Token-based theming — colors, spacing, typography
  • Component library — Button, Input, Modal (Storybook docs)
  • Composition API — variants, sizes, accessibility baked in
  • Versioning + changelog — consumers pin major versions

Enterprise architecture

  • Feature folders or domain-driven structure
  • Shared UI kit + API client layer
  • Env-based config, feature flags
  • Monorepo (Turborepo/Nx) — apps + packages
  • CI/CD — lint, test, build, preview deploys per PR
