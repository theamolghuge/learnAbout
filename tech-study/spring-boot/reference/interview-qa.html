IoC & DI

What problem does Dependency Injection solve?

Without it, a class constructs its own dependencies directly (new UserRepository()), tightly coupling it to a specific implementation and making it hard to test or swap implementations. DI has the container supply pre-built dependencies to the class instead, so the class only depends on an abstraction, is trivially testable with mocks, and implementations can be swapped via configuration.

Why is constructor injection preferred over field injection?

Constructor injection makes dependencies explicit and lets fields be final (immutable, guaranteed non-null after construction), fails fast at startup if a dependency is missing, and allows plain new instantiation in unit tests with no Spring context or reflection needed. Field injection hides dependencies, requires reflection to set (harder to test), and can't be final.

What's the difference between @Autowired on a constructor vs required=false behavior?

By default, @Autowired requires a matching bean to exist or the context fails to start. With a single constructor, @Autowired is optional — Spring infers it automatically. @Autowired(required = false) allows the dependency to be null if no bean is found, though this is rarely the right call — better to make the dependency truly optional via Optional<T> or a no-op default bean.

Beans

What's the actual difference between @Component, @Service, and @Repository?

Functionally, @Service and @Repository are both meta-annotated with @Component, so Spring treats them identically for scanning/DI purposes. The difference is semantic (documents the layer) plus one real behavior: @Repository triggers Spring's exception translation, converting database-specific exceptions into its unchecked DataAccessException hierarchy.

Default bean scope, and why does it matter for thread safety?

Singleton — one shared instance per container, reused by every thread handling every request. Because many request threads can call the same bean instance concurrently, storing per-request mutable state in an instance field is a race condition. Beans should generally be stateless; state belongs in method parameters/local variables or an explicitly-scoped bean (request/session/prototype).

When would you use @Bean inside a @Configuration class instead of @Component?

When you need to register a class you don't own/can't annotate — e.g. a third-party class like RestTemplate or an ObjectMapper — or when bean creation needs custom logic (conditional setup, builder pattern) that can't be expressed via a class-level stereotype annotation.

Spring Boot

What does @SpringBootApplication actually do?

It's a composite of three annotations: @Configuration (this class can define beans), @EnableAutoConfiguration (turn on classpath-based auto-configuration), and @ComponentScan (scan this package and sub-packages for stereotype-annotated beans).

Explain auto-configuration with a concrete example.

Spring Boot inspects what's on the classpath and configures sensible-default beans accordingly — e.g. if it sees a JDBC driver and spring-boot-starter-data-jpa on the classpath, plus datasource properties in application.yml, it auto-configures a DataSource, EntityManagerFactory, and TransactionManager for you. If you define your own bean of a given type, Boot's auto-configuration backs off and uses yours instead (conditional-on-missing-bean).

What's the point of the embedded server?

Traditional Java web apps were packaged as a WAR and deployed into a separately-installed app server (Tomcat/JBoss). Spring Boot bundles Tomcat (or Jetty/Undertow) directly inside the executable jar — java -jar app.jar starts a fully running web server with no external installation, which is what makes Spring Boot apps trivial to containerize.

Config

What are Spring profiles for?

Swapping configuration per environment (dev/test/prod) without changing code — e.g. a different DB URL or logging level per profile, defined in profile-specific YAML sections or files, activated via spring.profiles.active.

What's the property resolution precedence when the same key is set in multiple places?

Roughly: command-line arguments override environment variables, which override profile-specific application.yml, which overrides the base application.yml. This lets ops override any setting at deploy time without rebuilding the jar.

HTTP

What does idempotent mean, and which HTTP methods are idempotent?

Calling the operation once has the same effect as calling it many times with the same input. GET, PUT, and DELETE are idempotent by spec — PUT with the same body always ends in the same resource state, DELETE-ing an already-deleted resource is still "deleted." POST is not idempotent — resubmitting creates a duplicate. This matters for safe retry behavior on flaky networks.

401 vs 403 — what's the difference?

401 Unauthorized means the request isn't authenticated at all (missing/invalid credentials) — the client should log in. 403 Forbidden means the client IS authenticated but doesn't have permission for this specific action — logging in again won't help.

REST

What's the difference between @PathVariable and @RequestParam?

@PathVariable binds a segment of the URL path itself, e.g. the 10 in /users/10 — used for identifying a specific resource. @RequestParam binds a query string parameter, e.g. ?role=admin in /users?role=admin — used for filtering, pagination, or optional modifiers.

How does Spring convert a Java object returned from a @RestController method into a JSON HTTP response?

@RestController implies @ResponseBody on every handler method, which tells Spring MVC to run the return value through an HttpMessageConverter instead of resolving it as a view name. With spring-boot-starter-web on the classpath, Jackson is auto-configured as that converter, serializing the POJO to JSON automatically.

What status code should a successful POST that creates a resource return, and what should accompany it?

201 Created, ideally with a Location header pointing at the URL of the newly created resource (e.g. /users/42), and typically the created resource in the response body.
