1. Node.js Architecture — V8 & libuv

┌─────────────────────────────────────┐
│  Your JavaScript (single thread)    │
│  Call Stack · V8 Engine             │
├─────────────────────────────────────┤
│  Node.js Bindings (C++)             │
│  fs · http · crypto · events        │
├─────────────────────────────────────┤
│  libuv — Event Loop + Thread Pool   │
│  epoll/kqueue/IOCP · 4 worker threads│
└─────────────────────────────────────┘
ComponentRole
V8Google's JS engine — parses, compiles (JIT), executes JS, manages heap/GC
libuvEvent loop, async I/O, thread pool (default 4 threads for fs/crypto/DNS)
Call stackSync JS execution — one frame per function call
Thread poolOffloads blocking work so main thread stays free

Best for: I/O-heavy — APIs, realtime, streaming. Not for: CPU-bound on main thread — use Worker Threads or separate service.

4. Node.js Event Loop ⭐

  1. Timers — setTimeout, setInterval
  2. Pending callbacks — deferred I/O
  3. Idle, prepare — internal
  4. Poll — retrieve new I/O events; execute I/O callbacks
  5. Check — setImmediate
  6. Close — socket.on('close')
console.log("start");
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("promise"));
console.log("end");
// start, end, nextTick, promise, then timeout OR immediate
APIPriority
process.nextTickHighest — before event loop continues (can starve I/O)
Microtasks (Promises)After nextTick, before next phase
setImmediateCheck phase — after poll
setTimeoutTimers phase

Blocking the loop: sync fs, tight loops, huge JSON.parse — all requests wait. Fix: async APIs, Workers, chunk work.

5. EventEmitter

const EventEmitter = require("events");

class OrderService extends EventEmitter {
  placeOrder(order) {
    this.emit("order:placed", order);
  }
}

const svc = new OrderService();
svc.on("order:placed", (o) => sendEmail(o));
svc.once("ready", init);           // one-time
svc.removeListener("ready", init); // cleanup — prevent leaks

Streams, HTTP servers, and many Node APIs extend EventEmitter — pub/sub at the core of Node's design.

9. Express & Middleware

const app = express();
app.use(helmet());
app.use(express.json({ limit: "1mb" }));
app.use(cors({ origin: allowedOrigins }));
app.use(requestLogger);

app.get("/api/users/:id", auth, async (req, res, next) => {
  try {
    const user = await userService.findById(req.params.id);
    if (!user) return res.status(404).json({ error: "Not found" });
    res.json(user);
  } catch (err) { next(err); }
});

// 404 then error handler LAST
app.use((req, res) => res.status(404).json({ error: "Not found" }));
app.use((err, req, res, next) => {
  logger.error(err);
  res.status(err.status || 500).json({ error: err.message });
});

Middleware: (req, res, next) — runs in order. next() continue, next(err) jump to error handler.

11. API Validation

// Zod example
const CreateUser = z.object({
  email: z.string().email(),
  name: z.string().min(1).max(100),
  age: z.number().int().min(18).optional(),
});

app.post("/users", (req, res, next) => {
  const result = CreateUser.safeParse(req.body);
  if (!result.success) {
    return res.status(422).json({ errors: result.error.flatten() });
  }
  // use result.data — typed and validated
});

Validate at boundary — never trust req.body, query params, or headers. Reject early with 422.

13. Authentication & Authorization

Authentication — who are you?

// JWT flow
const token = jwt.sign({ sub: user.id, roles: user.roles }, SECRET, { expiresIn: "15m" });

function authMiddleware(req, res, next) {
  const header = req.headers.authorization;
  if (!header?.startsWith("Bearer ")) return res.status(401).json({ error: "Unauthorized" });
  try {
    req.user = jwt.verify(header.slice(7), SECRET);
    next();
  } catch { res.status(401).json({ error: "Invalid token" }); }
}

Authorization — what can you do?

function requireRole(...roles) {
  return (req, res, next) => {
    if (!roles.some(r => req.user.roles.includes(r))) {
      return res.status(403).json({ error: "Forbidden" });
    }
    next();
  };
}

app.delete("/api/users/:id", auth, requireRole("admin"), deleteUser);

14. SQL, Transactions & Prisma

// Parameterized query — prevent SQL injection
const result = await pool.query(
  "SELECT * FROM users WHERE email = $1",
  [email]
);

// Transaction
const client = await pool.connect();
try {
  await client.query("BEGIN");
  await client.query("INSERT INTO orders ...", [order]);
  await client.query("UPDATE inventory SET qty = qty - 1 ...", [sku]);
  await client.query("COMMIT");
} catch (e) {
  await client.query("ROLLBACK");
  throw e;
} finally {
  client.release();
}

Prisma ORM

const user = await prisma.user.create({ data: { email, name } });

await prisma.$transaction(async (tx) => {
  const order = await tx.order.create({ data: { userId, total } });
  await tx.product.update({ where: { id }, data: { stock: { decrement: 1 } } });
});

15. Redis & Caching

// Cache-aside pattern
async function getUser(id) {
  const cached = await redis.get(`user:${id}`);
  if (cached) return JSON.parse(cached);

  const user = await db.findUser(id);
  await redis.setex(`user:${id}`, 3600, JSON.stringify(user)); // TTL 1hr
  return user;
}

// Session store
await redis.set(`session:${sid}`, JSON.stringify(session), "EX", 86400);

16. Security

  • Helmet — secure HTTP headers (CSP, HSTS, X-Frame-Options)
  • Rate limiting — express-rate-limit, Redis-backed for distributed
  • Input validation — Zod/Joi at every boundary
  • Parameterized queries — no string concatenation SQL
  • Secrets — env vars, never in code/git
  • HTTPS — TLS in production
  • Dependency audit — npm audit, Dependabot
  • Least privilege — DB user permissions, IAM roles

// Consumer — separate worker process

Kafka (event streaming)

  • Durable log — topics, partitions, consumer groups
  • Replay events, high throughput, decoupled services
  • Use for event-driven microservices, analytics pipelines

WebSockets

const { WebSocketServer } = require("ws");
const wss = new WebSocketServer({ server });
wss.on("connection", (ws) => {
  ws.on("message", (data) => broadcast(data));
});

GraphQL

Single endpoint, client specifies shape — avoids over/under fetching. Trade-off: complexity, caching harder than REST, N+1 needs DataLoader.

Rate limiting

// Token bucket / sliding window — Redis for multi-instance
const key = `rate:${req.ip}`;
const count = await redis.incr(key);
if (count === 1) await redis.expire(key, 60);
if (count > 100) return res.status(429).json({ error: "Too many requests" });

20. Performance & Memory

  • Async I/O everywhere — no sync fs/crypto on request path
  • Connection pooling — DB, Redis, HTTP keep-alive
  • Streams for large payloads
  • Profile: node --inspect, clinic.js, 0x flame graphs
  • Memory: watch heap growth, listener leaks, unclosed connections
  • Graceful shutdown — SIGTERM → stop accepting → drain → close DB → exit
process.on("SIGTERM", async () => {
  server.close();
  await pool.end();
  await redis.quit();
  process.exit(0);
});

22. Distributed Systems & Architecture

Microservices

  • Independent deploy, own DB per service
  • Communication: REST, gRPC, message queues
  • Challenges: distributed transactions, observability, versioning

CAP theorem

In partition, choose Consistency or Availability. CP: bank transfers. AP: social feeds. Most systems are tunable — not purely one.

Patterns

PatternSolves
SagaDistributed transaction — compensating actions on failure
CQRSSeparate read/write models — scale reads independently
Event sourcingStore events not state — replay to rebuild
OutboxAtomic DB write + event publish via outbox table + poller
IdempotencySame request twice = same result — idempotency keys
Circuit breakerStop calling failing service — fail fast, recover gradually
Distributed lockRedis Redlock — coordinate exclusive access
Eventual consistencyReplicas converge over time — design UX for stale reads

Service discovery & tracing

  • Consul, Eureka, K8s DNS — services find each other
  • OpenTelemetry + Jaeger — trace ID across microservices
  • API Gateway — auth, rate limit, routing at edge
