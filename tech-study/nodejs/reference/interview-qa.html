Basics & Architecture

What is Node.js?

A JavaScript runtime built on V8 that runs JS outside the browser. It adds APIs for file system, networking, and OS interaction. Designed for event-driven, non-blocking I/O — ideal for APIs, realtime apps, and streaming.

Is Node.js single-threaded or multi-threaded?

JavaScript execution is single-threaded (one call stack). But Node uses libuv's thread pool for some I/O (file system, DNS) and supports Worker Threads and cluster for parallelism. The event loop itself runs on one thread.

When should you NOT use Node.js?

CPU-intensive tasks that block the event loop — heavy computation, image processing, complex ML on the main thread. Use Worker Threads, offload to a separate service, or pick a language better suited for CPU-bound work.

What is the difference between Node.js and Express?

Node.js is the runtime. Express is a minimal web framework built on Node's http module — it adds routing, middleware, and convenience APIs. You can build servers with raw Node; Express simplifies HTTP APIs.

What is libuv?

A C library that provides Node's event loop, thread pool, and async I/O. It abstracts platform-specific async operations (epoll on Linux, kqueue on macOS, IOCP on Windows) so Node works cross-platform.

Modules & npm

CommonJS vs ES Modules in Node?

CommonJS uses require/module.exports, loads synchronously at runtime. ESM uses import/export, supports static analysis and top-level await. Enable ESM with "type":"module" in package.json or .mjs files.

How do you get __dirname in ESM?

import { fileURLToPath } from "url"; import { dirname } from "path"; const __filename = fileURLToPath(import.meta.url); const __dirname = dirname(__filename);

What is the difference between dependencies and devDependencies?

dependencies are required at runtime in production. devDependencies are only for development — testing, linting, build tools. npm install --production skips devDependencies.

What is package-lock.json for?

Locks exact versions of every installed package (including nested dependencies) so installs are reproducible across machines and CI. Commit it to version control.

What is npx?

Runs packages without globally installing them — downloads temporarily and executes. Example: npx create-react-app my-app. Also runs locally installed binaries from node_modules/.bin.

Event Loop

Explain the Node.js event loop phases.

Timers (setTimeout/setInterval) → Pending callbacks → Idle/Prepare → Poll (I/O) → Check (setImmediate) → Close callbacks. Between phases, microtasks (Promises) and nextTick callbacks run.

Difference between process.nextTick and setImmediate?

process.nextTick runs before the event loop continues — highest priority async, can starve I/O if overused. setImmediate runs in the Check phase after Poll — designed to run after current I/O callbacks.

What happens if you block the event loop?

All other requests and callbacks wait — the server becomes unresponsive. Long synchronous operations (big JSON.parse, sync fs, tight loops) block everything. Fix with async APIs, Worker Threads, or breaking work into chunks.

setImmediate vs setTimeout(fn, 0) in Node?

Inside I/O callbacks, setImmediate runs before setTimeout(0). At top level, order can vary. setImmediate is Node-specific; setTimeout is cross-platform.

Core Modules

Difference between fs.readFile and fs.createReadStream?

readFile loads the entire file into memory — fine for small files. createReadStream reads in chunks — memory-efficient for large files. Streams are preferred for big data or piping.

What is a Buffer?

A fixed-size chunk of raw binary data in Node. Used for file I/O, network protocols, and crypto. Created with Buffer.from(), Buffer.alloc(). Convert with .toString('utf-8') or .toString('base64').

What is EventEmitter?

Node's pub/sub pattern. Objects emit named events; listeners register with .on(). Many Node APIs inherit from EventEmitter (streams, HTTP server). Use .once() for one-time listeners, .removeListener() to clean up.

How do you read environment variables?

process.env.VARIABLE_NAME. Load from .env files with the dotenv package in development. In production, set env vars through your host (Docker, Kubernetes, cloud platform) — never commit secrets.

Express & HTTP

What is middleware in Express?

Functions with signature (req, res, next) that run in order. They can read/modify req/res, end the response, or call next() to pass to the next middleware. Used for parsing, auth, logging, error handling.

How does Express error handling work?

Error-handling middleware has 4 parameters: (err, req, res, next). Pass errors with next(err) from route handlers. Express skips normal middleware and jumps to the first error handler. Always put it last.

What is the difference between app.use and app.get?

app.use matches all HTTP methods and all paths (or a path prefix) — typically for middleware. app.get only matches GET requests to a specific route — for route handlers.

How do you parse JSON request bodies?

app.use(express.json()) — built-in middleware that parses JSON bodies and sets req.body. For URL-encoded forms: express.urlencoded({ extended: true }).

What is CORS and how do you handle it in Express?

Cross-Origin Resource Sharing — browsers block requests from one origin to another unless the server allows it. Use the cors middleware or set headers manually: Access-Control-Allow-Origin, methods, headers.

Async Patterns

How do you convert callback-based APIs to Promises?

const { promisify } = require('util'); const readFile = promisify(fs.readFile); Or use built-in promise versions: require('fs/promises') in modern Node.

What is an error-first callback?

Node convention: callback signature is (err, result). If err is truthy, something failed — handle it first. If null, operation succeeded and result has data. Legacy pattern before Promises/async-await.

How do you handle unhandled promise rejections?

Listen on process.on('unhandledRejection', (reason) => {...}). Log and exit gracefully in production — unhandled rejections can leave the app in a bad state. Always use try/catch with async route handlers.

Streams

What are the four types of streams?

Readable (read data — fs.createReadStream), Writable (write data — fs.createWriteStream), Duplex (both — TCP socket), Transform (modify while passing through — zlib gzip).

What does .pipe() do?

Connects a readable stream to a writable stream — data flows automatically, handles backpressure. Example: readStream.pipe(writeStream). Preferred over manually listening to 'data' events for piping.

What is backpressure?

When a writable stream can't keep up with readable data, it signals to slow down. Streams handle this internally with .pipe(). Without it, memory can grow unbounded if you keep writing faster than consuming.

Security & Production

How do you implement graceful shutdown?

Listen for SIGTERM/SIGINT, stop accepting new connections with server.close(), finish in-flight requests, close DB connections, then process.exit(0). Kubernetes sends SIGTERM before killing pods.

What security practices for Node APIs?

Validate/sanitize input, use Helmet for headers, rate limiting, parameterized queries (no SQL injection), env vars for secrets, keep dependencies updated, HTTPS in production, principle of least privilege.

What is the purpose of NODE_ENV?

Convention: development vs production. Frameworks and libraries change behavior — e.g. Express disables verbose errors in production, React enables optimizations. Set it in production deployments.

Advanced

Cluster vs Worker Threads?

Cluster forks separate Node processes — each has its own memory, shares nothing by default. Good for scaling HTTP across CPU cores. Worker Threads share memory (SharedArrayBuffer), lighter — good for CPU-heavy tasks without full process overhead.

How does Node handle concurrent connections?

Non-blocking I/O — when waiting for DB/network, the event loop handles other requests. One thread can serve thousands of concurrent connections if work is I/O-bound. Not true parallelism for CPU work on one thread.

What is the difference between spawn and exec?

child_process.spawn streams output — good for long-running processes. exec buffers entire stdout/stderr into memory — fine for short commands. Both run shell commands from Node.

How would you debug a memory leak in Node?

Monitor heap with process.memoryUsage(), take heap snapshots with Chrome DevTools (node --inspect), look for growing listeners (EventEmitter leaks), unclosed connections, or global caches that never clear.

SQL, Transactions & ORM

How do you prevent SQL injection?

Always use parameterized queries / prepared statements — pass user input as parameters, never concatenate into SQL strings. ORMs like Prisma parameterize by default. Also validate input types at API boundary.

Explain database transactions and ACID.

Transaction groups operations atomically — all succeed (COMMIT) or all roll back (ROLLBACK). ACID: Atomicity (all or nothing), Consistency (valid state), Isolation (concurrent txs don't interfere), Durability (committed data survives crashes).

What is the N+1 query problem?

Loading a list then firing one query per item (1 + N queries). Fix with JOIN, eager loading (include in Prisma), or batch loading (DataLoader). Kills performance at scale.

Redis & Caching

Explain the cache-aside pattern.

App checks cache first. On miss, read from DB, write to cache with TTL, return data. On write/update, invalidate or update cache key. Simple, works with any cache. Watch for cache stampede on expiry.

When to use Redis vs in-memory cache?

In-memory (Map/LRU): single process, fast, lost on restart. Redis: shared across multiple Node instances, persistence options, pub/sub, rate limiting — required for horizontal scaling.

Authentication & Authorization

Authentication vs authorization?

Authentication: verify who the user is (login, JWT) — 401 Unauthorized. Authorization: verify what they're allowed to do (roles, permissions) — 403 Forbidden. Auth first, then authz on protected routes.

JWT best practices in Node APIs?

Short-lived access tokens (15min), refresh token in httpOnly secure cookie, validate signature and expiry on every request, store minimal claims, rotate secrets, never put secrets in JWT payload.

Distributed Systems

What is the Saga pattern?

Manages distributed transactions across microservices without 2PC. Each step has a compensating action if a later step fails — e.g. cancel payment if shipping fails. Choreography (events) or orchestration (coordinator).

What is idempotency and why does it matter?

Same request processed multiple times produces same result. Critical for retries, network failures, webhooks. Implement with idempotency keys stored in DB/Redis — reject or return cached result for duplicate keys.

Explain the Outbox pattern.

Write business data and an outbox event row in the same DB transaction. Separate poller reads outbox and publishes to message broker. Guarantees at-least-once delivery without dual-write inconsistency.

What is a circuit breaker?

Stops calling a failing downstream service after threshold — fail fast instead of cascading timeouts. States: closed (normal), open (reject), half-open (test recovery). Libraries: opossum, resilience4j patterns.

CAP theorem in practice?

During network partition, choose Consistency (CP — reject writes until synced) or Availability (AP — accept writes, reconcile later). Most production systems tune per operation — not purely CP or AP.

Kafka vs RabbitMQ?

Kafka: durable log, replay, high throughput, event streaming, consumer groups. RabbitMQ: traditional message broker, routing patterns, task queues, messages deleted after ack. Kafka for event sourcing/analytics; Rabbit for job queues.
