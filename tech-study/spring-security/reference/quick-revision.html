30-second answers

Why is JWT auth "stateless"?
Every request self-validates via signature + expiry — no server-side session store needed.

Why two tokens (access + refresh)?
Short access token limits leak damage; refresh token renews it without re-login.

401 vs 403, one more time?
401 = not authenticated. 403 = authenticated, not permitted.

End-to-end flow

POST /auth/register → hash password (BCrypt) → save → 201
POST /auth/login → verify hash → issue access + refresh tokens → 200
GET /users/profile
  Authorization: Bearer 
  → JwtAuthFilter validates → SecurityContext populated
  → authorizeHttpRequests / @PreAuthorize check → 200 or 401/403

Implement from memory

  • A SecurityFilterChain bean: permitAll /auth/**, authenticated everything else, stateless session
  • JWT issue + validate (sign with secret, check expiry)
  • @PreAuthorize("hasRole('ADMIN')") on a controller method
  • Explain refresh token rotation out loud in 30 seconds
